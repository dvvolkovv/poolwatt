# Возврат ошибочного чека и журнал изменений — план (§46)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development
> (recommended) or superpowers:executing-plans to implement this plan
> task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** чек становится документом (замораживается в момент выдачи),
бухгалтер возвращает ошибочный чек в поддержку, поддержка выпускает
исправленную версию, и каждое изменение видно в журнале.

**Architecture:** снимок `ReceiptDocument` ложится в `Receipt.document`;
`readReceiptDocument` отдаёт снимок всем читателям; `ReceiptClaim` несёт
заявку и её решение, `ReceiptCorrection` — журнал «было/стало»; исправление
выпускает новый `Receipt` с `correctsReceiptId`, а книга месяца печатает номер
действующей версии.

**Tech Stack:** Next.js 16 (App Router), Prisma, vitest, Playwright.

Спецификация: `docs/superpowers/specs/2026-11-27-receipt-corrections-design.md`.

## Где работа отошла от плана

- **Главное нашлось до первой строки кода.** Чек собирался заново при каждом
  открытии, поэтому правка реквизитов или ставки НДС у партнёра молча
  переписывала все прошлые чеки. Заморозка документа (`receipt-store.ts`) не
  была «частью 1» для порядка — без неё исправлять было нечего.
- **Письма не ждут нажатия.** Первый прогон e2e падал на том, что почтовый
  сервер ответил «Ratelimit exceeded» через десять секунд, и всё это время
  бухгалтер смотрел на кнопку. Уведомления ушли из запроса (`void` + лог):
  заявка в очереди, а письмо — вежливость сверху.
- **Исправленная версия не имеет своего платежа** (`Payment` — один чек), и
  из-за этого ни водитель, ни бухгалтер не могли её открыть. Доступ теперь
  идёт по цепочке: новая версия принадлежит тому, кому принадлежал исходный
  документ. Страница проверки по QR по той же причине берёт пункт и сеть из
  снимка, а не из связей.
- **`MAIL_STUB` на весь прогон тестов.** Обнаружилось по дороге: тесты
  выполняются с настоящими ключами этого сервера, то есть каждый тест, который
  кого-то уведомляет, отправлял живое письмо на выдуманный адрес. Теперь
  `vitest.config.ts` ставит заглушку, а `email.test.ts` снимает её для себя.
  Прогон по чекам ускорился с 14 секунд до двух.
- **Строка месяца показывает последнюю заявку.** Документ можно вернуть
  дважды (после ответа), и карта заявок по чеку оставляла старую.
- **Проверка «journal» в e2e смотрит на состояние карточки, а не на сообщение
  в форме:** после ответа страница перерисовывается и форма исчезает вместе с
  надписью.
