# План: бронирование разъёмов (Блок G)

Спецификация: `docs/superpowers/specs/2026-11-24-reservations-design.md`

Четыре истории, три части.

## Часть 1. US-32 — условия брони

- [ ] Миграция: `ReservationPolicy`, `Reservation`, статус разъёма `BOOKED`,
      ссылка на бронь в `Receipt`.
- [ ] `reservation-policy.ts`: чтение с умолчаниями, сохранение, журнал.
- [ ] Тесты `reservation-policy.test.ts`.
- [ ] Форма условий на карточке пункта в кабинете сети.
- [ ] Ключи en/ru/sk. Прогон, сборка, коммит.

## Часть 2. US-30 — бронь

- [ ] `reservation-service.ts`: создание в одной транзакции со всеми
      проверками §34, копия условий, плата и гарантия на кошельке,
      разъём `BOOKED`; отмена до и после порога.
- [ ] Тесты `reservation-service.test.ts`.
- [ ] Фильтр «свободен сейчас» не показывает забронированное.
- [ ] Форма брони на карточке пункта и «мои брони» в кабинете.
- [ ] Ключи en/ru/sk. Прогон, сборка, коммит.

## Часть 3. US-33 и US-55 — неявка и поломка

- [ ] Неявка: закрытие по окончании окна, штраф из гарантии, чек, письмо.
- [ ] Поломка разъёма отменяет брони без штрафа, письмо с альтернативами.
- [ ] Воркер раз в минуту.
- [ ] Тесты.
- [ ] Ключи en/ru/sk. Прогон, сборка, коммит.
