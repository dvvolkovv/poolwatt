# Роуминг: списание по правилам клиринга (US-11)

Дата: 2026-11-25. Раздел ТЗ: §8 «Роуминг», §9.10, §16.6, §24.2, §46.
История: US-11 (P1) «Хочу пользоваться балансом кВт·ч в другой стране».
Критерии приёмки: списание в зоне роуминга по правилам клиринга; пользователь
видит курс пересчёта до подтверждения.

## Что уже есть

- `src/lib/exchange/roaming.ts` — арифметика пересчёта: курс как отношение
  спотовых ориентиров зон, комиссия партнёра в кВт·ч, округление вверх.
- `src/lib/exchange/roaming-service.ts` — `quoteRoaming` (какая зона домашняя,
  какой партнёр держит коридор, сколько покрывает баланс) и
  `upsertRoamingAgreement` (коридор заводит оператор).
- `POST /v1/roaming/quote` — курс до подтверждения, ничего не меняет.
- Таблица `RoamingAgreement`: пара зон, партнёр, комиссия, суточный предел.

## Чего нет

1. Списания: курс считается, но ни один киловатт-час в зоне роуминга не
   списывается с домашнего баланса. Зарядка в чужой зоне сегодня идёт мимо
   роуминга — кошелёк зоны пуст, и всё докупается на бирже за деньги.
2. Реестра взаиморасчётов: нечего предъявить партнёру и нечем ограничить
   суточный оборот по §24.2 (сейчас предел действует «на сессию», потому что
   накопленного за день просто негде взять).
3. Страницы: курс отдаёт только метод API, а по правилу реестра метод без
   страницы — это «частично».

## Решение

### 1. Роуминг — ступень водопада §16.6

Порядок источников для сессии в зоне V становится таким:

1. подарок партнёра (§43);
2. баланс кВт·ч в зоне V;
3. **роуминг: баланс в домашней зоне H, пересчитанный по коридору H→V;**
4. рыночная заявка в зоне V (§16.6);
5. агрегатор по внешнему споту (§16.7).

Роуминг стоит раньше биржи осознанно: §8 обещает, что купленные в одной
стране киловатт-часы можно потратить в другой, — значит, свои кВт·ч тратятся
раньше, чем за деньги покупаются новые.

`planCharge` остаётся чистой функцией и получает одну новую возможность:

```ts
roaming?: {
  /** кВт·ч зоны V, которые коридор готов обслужить (уже с учётом баланса и предела) */
  maxKwh: number;
  conversionRate: number;
  feePct: number;
} | null
```

и отдаёт `kwhFromRoaming`, `roamingDebitKwh` (сколько уйдёт из домашнего
баланса), `roamingFeeKwh`, плюс источник `"roaming"`.

Деньги за роуминговые кВт·ч не берутся: энергию в зоне V отдал партнёр, а
расплатился водитель своими домашними кВт·ч и комиссией в кВт·ч. Поэтому
`energyCost` они не увеличивают, и комиссия §16.9 на них не начисляется —
она считается с потраченных денег, а их здесь нет.

В `roaming.ts` добавляются две чистые функции рядом с `roamingQuote`:

- `roamingDebit(amountKwh, rate, feePct)` → `{ convertedKwh, feeKwh, totalKwh }`
  — то же, что считает `roamingQuote`, но без баланса и зон;
- `roamingAffordableKwh(balanceKwh, rate, feePct)` → сколько кВт·ч зоны V
  целиком покрывает домашний баланс. Округление вниз по сетке 0,001 и проверка
  обратным счётом: после округления вверх в `roamingDebit` долг не должен
  превысить баланс.

### 2. Таблица `RoamingSettlement`

Одна строка на одну роуминговую сессию — то, что предъявляется партнёру:

| поле | смысл |
| --- | --- |
| `agreementId` | коридор H→V и его партнёр |
| `userId`, `paymentId` | чей сеанс и какой платёж (уникален: повтор не удвоит строку) |
| `deliveredKwh` | кВт·ч, которые партнёр выдал в зоне V |
| `debitedKwh` | кВт·ч, сожжённые в домашней зоне |
| `feeKwh` | из них комиссия коридора |
| `conversionRate` | курс на момент сеанса, не пересчитывается потом |
| `burnedTokenIds` | какие партии сожжены — для сверки §16.11 |
| `status` | `OPEN` → `NETTED` |
| `nettedAt`, `nettedRef` | когда и по какому документу закрыт взаимозачёт |

Строка пишется в той же транзакции, что сожжение партий и чек. Платёж —
уникальный ключ, поэтому повтор с тем же `Idempotency-Key` возвращает прежний
ответ и второй строки не создаёт.

### 3. Суточный предел §24.2 становится суточным

`dailyLimitKwh` коридора теперь сравнивается с суммой `deliveredKwh` того же
пользователя по тому же коридору за календарные сутки UTC, а не с объёмом
одной сессии.

- `POST /v1/roaming/quote` на объём больше остатка отказывает с указанием
  остатка: метод отвечает на вопрос «можно ли столько», и ответ «нет».
- Сессия зарядки обслуживает роумингом ровно остаток, а всё, что выше,
  уходит на биржу или агрегатору: водителя нельзя оставить без энергии из-за
  предела, который касается только коридора.

### 4. Страница водителя `/me/roaming`

ТЗ §9.10 — «при зарядке в другой стране показывается пересчёт до
подтверждения». Два блока:

1. **Коридоры**: откуда и куда, партнёр, курс сейчас, комиссия, остаток
   суточного предела. Коридора нет — так и сказано.
2. **Сеанс**: выбрать зону и объём → «Рассчитать» показывает курс,
   пересчитанный объём, комиссию в кВт·ч, итог списания из домашнего
   баланса, что докупается на бирже и за какие деньги; и только после этого
   «Подтвердить». Ключ идемпотентности рождается на один расчёт. После
   подтверждения открывается чек.

### 5. Чек (§46)

В разбивку чека добавляются строки роуминга: домашняя зона, партнёр, курс,
сожжённые домашние кВт·ч, комиссия коридора. Страница чека их печатает —
иначе водитель не увидит, по какому курсу с него списали.

### 6. Страница оператора `/admin/roaming`

- коридоры: создание и правка (партнёр, комиссия, суточный предел,
  включён) — сейчас `upsertRoamingAgreement` не вызывает ни одна страница;
- позиции: по каждому партнёру открытые сеансы, выданные в роуминге кВт·ч,
  списанные домашние кВт·ч, удержанная комиссия;
- «закрыть период»: оператор вписывает номер документа, строки становятся
  `NETTED` с записью в `AuditLog`.

Денежный перевод партнёру не делается и не выдумывается: взаимозачёт
закрывается вне системы, а оператор фиксирует, чем именно он закрыт. Это тот
же путь, что у KYB-проверки руками.

## Проверка

- `roaming.test.ts` — `roamingDebit`, `roamingAffordableKwh`: курс в обе
  стороны, нулевая комиссия, пыль 0,001, баланс, которого хватает ровно.
- `charge.test.ts` — водопад с роумингом: порядок источников, предел
  коридора, роуминг без денежной стоимости, нулевой `maxKwh`.
- `roaming-service.test.ts` — суточный остаток по коридору считается из
  сеансов за сутки; вчерашние не считаются.
- `roaming-flow.test.ts` (интеграционный) — сеанс в чужой зоне сжигает
  домашние партии, пишет `RoamingSettlement`, кладёт курс в чек; повтор с тем
  же ключом не создаёт второй строки; две одновременные сессии с одним ключом
  дают одну строку; взаимозачёт закрывает период.
- e2e `roaming.spec.ts` — на живой сборке: страница показывает курс до
  подтверждения, после подтверждения баланс домашней зоны уменьшился на
  рассчитанную величину и чек открывается с курсом.

## Что остаётся за владельцем

- Настоящие партнёры по взаимозачёту и их тарифы (§8 «Правила конвертации
  между зонами и комиссия — отдельный документ»). В базе — заглушки нужной
  формы из сева.
- Денежный перевод по взаимозачёту: нужен счёт EMI.
- Поток сессий от чужой сети (OCPI): пока роуминговый сеанс подтверждает сам
  водитель на странице, как и в US-08.
