# Навигация сайта и установка приложения — спецификация

2026-11-28. Блок P1 плана мобильного запуска (`inbox/Poolwatt.md`, задача
Этапа 1 «список экранов и приоритеты» и требование владельца от 2026-11-28:
сложить разделы в гамбургер, упорядочить кнопки главной, дать возможность
поставить приложение с телефона).

## Что не так сегодня

Проверено на живой сборке, а не по памяти:

1. **На телефоне у сайта нет навигации вовсе.** Весь ряд ссылок в
   `src/components/navbar.tsx` стоит под `hidden md:flex`. На экране уже
   телефона остаётся логотип, переключатель языка и таблетка профиля.
   Попасть на `/navigator`, `/exchange`, `/contractors` можно только набрав
   адрес руками.
2. **Кнопки «Войти» на телефоне тоже нет** — `hidden md:inline-block`. То
   есть незашедший человек с телефона не может зайти.
3. **Три ссылки из семи в шапке ведут в 404.** `/ru/hubs`, `/ru/offers`,
   `/ru/watchlist` — проверено curl'ом по живой сборке, все три отдают 404.
   Разделов с такими адресами в `src/app/[locale]/` нет; комментарий в
   `navbar.tsx` честно называет их «Phase-2 routes» и отключает им
   prefetch, но из меню их никто не убрал.
4. **В подвале три таких же мёртвых ссылки:** `/hubs`, `/offers` и
   `/settings` (настройки живут на `/me/settings`).
5. **Поставить приложение на телефон неоткуда.** APK лежит и отдаётся
   (`https://poolwatt.com/downloads/poolwatt.apk`, 200, 4 МБ), PWA
   устанавливается, но ни одной ссылки на это с сайта нет, и приглашения
   «добавить на экран» тоже нет.

Пункты 3 и 4 — один и тот же изъян устройства, а не шесть опечаток: ссылки
живут списком внутри вёрстки, в двух местах, и ничто не проверяет, что
адрес ведёт на существующую страницу.

## Устройство решения

### 1. Один источник правды о разделах — `src/lib/site-nav.ts`

Разделы сайта становятся данными, а не разметкой:

```ts
export type NavAudience = "anyone" | "signedIn" | "operator";
export interface NavItem {
  key: string;
  href: string;
  audience: NavAudience;
}
export interface NavGroup {
  key: string;
  items: NavItem[];
}
export const SITE_NAV: NavGroup[];
export function visibleNav(ctx: {
  signedIn: boolean;
  operator: boolean;
}): NavGroup[];
```

`href` — путь без языка (`/navigator`), язык подставляет вызывающий. Шапка,
гамбургер и подвал читают один и тот же список. Ссылка перестаёт
существовать в двух местах с двумя адресами, а мёртвый адрес нельзя внести
мимо этого файла.

Группы, в порядке «что человеку нужно раньше»:

| Группа     | Разделы                                                                                                                                       | Кому                     |
| ---------- | --------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------ |
| `energy`   | Зарядные станции `/navigator`, Производители `/`, Биржа `/exchange`                                                                           | всем                     |
| `mine`     | Кабинет `/me`, Кошелёк `/me/wallet`, Брони `/me/bookings`, Избранное `/me/favorites`, Поддержка `/me/tickets`, Настройки `/me/settings`       | вошедшим                 |
| `partners` | Зарегистрировать дом `/me/build-requests/new`, Подрядчики `/contractors`, Листинг компании `/me/listing`, Сеть зарядок `/me/charger-operator` | последние два — вошедшим |
| `apps`     | Приложение на телефон `/install`                                                                                                              | всем                     |
| `operator` | Админка `/admin`                                                                                                                              | оператору                |

«Хабы», «Офферы» и «Избранное» по адресу `/watchlist` из меню уходят: двух
первых разделов нет в продукте, третий есть по адресу `/me/favorites`.

### 2. Тест, который ловит мёртвую ссылку

`src/lib/site-nav.test.ts`: для каждого `href` из `SITE_NAV` проверяется,
что на диске есть соответствующий `page.tsx` под `src/app/[locale]/`.
Статические сегменты сопоставляются именами папок. Это ровно тот тест,
который поймал бы `/hubs` год назад, и он же не даст внести мёртвый адрес
снова.

### 3. Гамбургер — `src/components/site-menu.tsx`

Клиентский компонент, одна панель на все ширины экрана:

- кнопка `<button aria-expanded aria-controls aria-label>`, площадь нажатия
  не меньше 44×44 CSS-пикселей;
- панель `role="dialog" aria-modal="true"` с подписью, выезжает справа;
- закрывается по Escape, по нажатию на затемнение и при смене адреса;
- при открытии фокус уходит в панель, при закрытии возвращается на кнопку;
- пока панель открыта, страница под ней не скроллится;
- внутри — `<nav>`, каждая группа со своим заголовком, разделы списком, с
  пунктами «Войти» или «Выйти» в конце;
- на мониторе в шапке остаётся короткий ряд из группы `energy`, и гамбургер
  рядом открывает ту же панель целиком. На телефоне ряда нет, есть только
  гамбургер.

Кнопка «Войти» перестаёт быть `hidden md:inline-block` — на телефоне она
внутри панели, то есть доступна.

### 4. Страница установки — `/{locale}/install`

Один экран, который честно говорит, что у человека в руках:

- **Android.** Кнопка «Установить» — системное приглашение PWA через
  событие `beforeinstallprompt`, если браузер его дал. Рядом прямая ссылка
  на APK `https://poolwatt.com/downloads/poolwatt.apk` с номером сборки и
  размером, и предупреждение, что это сборка вне Google Play, поэтому
  Android спросит разрешение на установку.
- **iOS.** Инструкция для Safari: «Поделиться» → «На экран „Домой“». Про
  TestFlight сказано словами: приглашение приходит на Apple ID, и добавить
  тестировщика может только владелец — **публичной ссылки на TestFlight мы
  не выдумываем**, её нет.
- **На мониторе** — QR с адресом этой же страницы (библиотека `qrcode` уже
  в дереве, ею печатается QR чека §46), чтобы открыть её на телефоне.
- Ссылка на страницу — в группе `apps` гамбургера и в подвале.

Страница ничего не обещает за внешние стороны: APK отдаёт наш nginx,
PWA ставит сам браузер, публикация в магазинах — отдельный открытый вопрос
владельцу.

### 5. Кнопки главной страницы

Сейчас в герое три кнопки подряд одного веса: «к производителям», «подать
заявку», «зарядки». Порядок случайный, и на телефоне они переносятся в три
строки.

Становится: **одно главное действие** — «Зарядные станции» (это то, зачем
на сайт приходит водитель), и два ровных второстепенных — «Производители»
и «Зарегистрировать дом». На телефоне главная кнопка во всю ширину, две
другие в ряд пополам. Высота кнопки не меньше 44 пикселей на всех ширинах.

### 6. Подвал

Читает `SITE_NAV` вместо своего списка. Мёртвые `/hubs`, `/offers` и
`/settings` уходят вместе с ним.

## Чего эта работа не делает

- Не трогает раздел `/{locale}/app` — телефонную оболочку. У неё своя
  нижняя панель на пять вкладок, и `ChromeGate` по-прежнему прячет там
  шапку и подвал сайта.
- Не добавляет уведомлений. Это следующий блок (Web Push).
- Не добавляет Телеграма. Это блок после него.
- Не открывает ни одного закрытого переключателя: оплата и внешние
  поставщики остаются там, где были.

## Проверка

- Юнит: `site-nav.test.ts` — каждый адрес из меню существует на диске;
  `visibleNav` отдаёт группу `mine` только вошедшему, `operator` только
  оператору, `apps` и `energy` — всем.
- e2e на Pixel 7 против живой сборки: на телефоне видна кнопка гамбургера;
  панель открывается, в ней есть «Зарядные станции» и «Войти»; переход по
  ссылке из панели приводит на страницу с кодом 200; Escape закрывает
  панель; фокус возвращается на кнопку.
- e2e на мониторе: ни одна ссылка шапки и подвала не отдаёт 404 — проход по
  всем адресам меню.
- Страница `/install` открывается на телефоне и на мониторе, ссылка на APK
  отдаёт 200.
