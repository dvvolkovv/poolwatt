# Конструктор подарков целиком (§42)

Дата: 2026-11-27. Разделы ТЗ: §42 («Конструктор подарков» — таблица
параметров), §43 (промо-токен), §33 и §34 (плата за бронь), §16.6 (водопад
оплаты), §46 (чек), §44 (аналитика кампаний).

Своей истории у §42 нет: US-41, US-42 и US-43 закрыли подарочные кВт·ч, а
остальные строки таблицы §42 остались несделанными и записаны в реестре как
отдельная история. Это она.

## Что из таблицы §42 уже работает и что нет

| Строка §42 | Сейчас |
| --- | --- |
| Триггер: первая зарядка, N-ная, объём за период | есть |
| Триггер: регистрация по QR-коду или промокоду партнёра | **нет** |
| Триггер: день рождения клиента | **нет** |
| Подарок: N подарочных кВт·ч | есть |
| Подарок: скидка в % на следующую зарядку | **нет** |
| Подарок: бесплатная бронь | **нет** |
| Подарок: комбинация | **нет** |
| Где действует: сеть или выбранные пункты | есть |
| Срок действия | есть |
| Ограничение: один раз на клиента | есть |
| Ограничение: минимальный объём следующей зарядки | **колонка есть, её никто не читает** |
| Ограничение: не суммируется с другими акциями | **нет** |
| Бюджет в кВт·ч, остановка при исчерпании | есть |
| Бюджет в деньгах | ждёт EMI (гейт) |
| Источник финансирования: выработка партнёра | есть |

Найдено по дороге и входит в эту работу: `Campaign.minNextChargeKwh`
сохраняется из формы и не проверяется ни в одной строке кода, то есть
ограничение ТЗ существует только на бумаге.

## Четыре решения владельца (подтверждены 2026-11-27)

1. **Скидка в % оплачивается энергией партнёра, не деньгами.** Скидка 20 % на
   сеанс 40 кВт·ч значит: 8 кВт·ч приходят из кошелька партнёра бесплатно,
   водитель платит за 32. Денежный бюджет кампании по-прежнему закрыт гейтом,
   и денег мы не выдумываем. Механизм — тот же `PromoGrant`, что у подарка
   §43: скидка это подарок, размер которого известен только в момент сеанса.
2. **День рождения — только день и месяц, без года, добровольно.** Меньше
   персональных данных; подарок работает так же.
3. **Промокод вводится в двух местах:** поле при регистрации и кнопка «у меня
   есть промокод» в кабинете. QR партнёра — ссылка с тем же кодом.
4. **«Не суммируется» = на один сеанс применяется один подарок,** самый
   выгодный водителю; у кампании есть галочка «не складывать с другими».

## Модель данных

```
enum CampaignTrigger { … PROMO_CODE  BIRTHDAY }
enum PromoGrantKind  { ENERGY  FREE_BOOKING }

Campaign
  promoCode    String?         // @@unique([operatorId, promoCode]), хранится в верхнем регистре
  discountPct  Decimal?(5,2)   // подарок «скидка N % на следующую зарядку»
  freeBooking  Boolean = false // подарок «бесплатная бронь»
  exclusive    Boolean = false // «не суммируется с другими акциями»
  budgetGrants Int?            // предел по числу подарков — для бесплатной брони
  issuedGrants Int = 0

PromoGrant
  kind        PromoGrantKind = ENERGY
  discountPct Decimal?(5,2)    // копия правила на момент выдачи

Reservation
  promoGrantId String?         // каким подарком оплачена бронь

User
  birthDay   Int?              // 1–31, без года
  birthMonth Int?              // 1–12
```

`amountKwh` у подарка-скидки — это **потолок**: сколько партнёр зарезервировал
из бюджета под эту скидку. Поэтому учёт бюджета, исчерпание кампании и
возврат несгоревшего остатка работают ровно как сегодня, без новых правил.

## Правила

**Скидка в %.** Подарок со `discountPct` отдаёт в сеанс не больше, чем
`pct %` от объёма сеанса, и не больше своего остатка. Для этого
`availableGiftKwh` и `spendGrants` получают объём сеанса: до сих пор им
хватало знать водителя и пункт.

**Не суммируется.** Если среди подходящих подарков есть хотя бы один от
кампании с `exclusive`, применяется ровно один подарок — тот, что даёт в этом
сеансе больше кВт·ч; при равенстве — тот, что раньше сгорает. Иначе порядок
прежний: раньше сгорает — раньше тратится.

**Минимальный объём следующей зарядки.** Подарок кампании с
`minNextChargeKwh` не участвует в сеансе меньше этого объёма — и в расчёте до
подтверждения, и в списании.

**Бесплатная бронь.** `createReservation` ищет у водителя живой подарок
`FREE_BOOKING` в сети этого пункта (та же проверка области, что у энергии).
Нашёлся — плата за бронь записывается нулём, подарок отмечается
использованным, бронь помнит его. Гарантийный залог остаётся: это
возвращаемые деньги, а не плата. Плата за продление (§33) подарком не
покрывается — подарок на одну бронь, и экран об этом говорит. Денег при этом
никуда не движется: плату за бронь берёт сам партнёр, и «бесплатно» означает,
что он её не берёт.

**Бюджет бесплатной брони.** Бронь не стоит кВт·ч, а денежный бюджет закрыт
гейтом, поэтому единственный честный предел — число подарков: `budgetGrants`.
Это шаг за пределы таблицы §42, где бюджет назван «в кВт·ч или в деньгах», и
он назван здесь прямо: иначе кампания с бесплатной бронью не останавливалась
бы вообще.

**Комбинация.** Одна кампания может дать и энергию (фиксированный объём или
скидку), и бесплатную бронь — это два подарка из одной кампании. Ключ «один
раз на клиента» у них разный (`once` и `once-booking`), поэтому уникальный
индекс остаётся как есть. Фиксированный объём вместе со скидкой в одной
кампании не предлагается: оба дают энергию, и партнёру для этого достаточно
двух кампаний.

**Промокод.** `redeemPromoCode(userId, code)` выдаёт подарок сразу, без
зарядки: код уникален внутри сети, регистр не важен, кампания должна быть
активной и в своём окне дат, «один раз на клиента» для такой кампании
включён принудительно. QR — ссылка `/{locale}/promo/<код>`, которая после
входа или регистрации делает то же самое. Уже существующий клиент сети тоже
может ввести код: отказывать ему значило бы, что наклейка на зарядке работает
только для новых, а §42 обещает подарок за приход по коду.

**День рождения.** Проход воркера раз в день выдаёт подарок клиентам сети, у
которых совпали день и месяц: клиент — тот, у кого в этой сети есть хотя бы
одна оплаченная зарядка (иначе партнёр дарил бы всем пользователям системы).
Ключ «один раз» — `birthday-<год>`, то есть раз в год и при двух проходах.
Родившимся 29 февраля подарок приходит 28-го в невисокосный год.

## Что видит человек

- Партнёр, `/me/charger-operator/[id]/campaigns`: в конструкторе появляются
  триггеры «по промокоду» (с полем кода и готовой ссылкой для QR) и «день
  рождения»; блок подарка — фиксированные кВт·ч, или скидка N % с потолком,
  или бесплатная бронь, или комбинация; ограничения — «один раз на клиента»,
  «минимальный объём следующей зарядки», «не суммируется»; бюджет в кВт·ч и
  предел по числу подарков.
- Водитель: поле «промокод» при регистрации и кнопка «у меня есть промокод» в
  разделе «Подарки» (кабинет и телефон); в списке подарков скидка показана как
  «−20 % на зарядку», бронь — как «бесплатная бронь»; в профиле появляется
  добровольный день и месяц рождения.
- Экран брони говорит, что эта бронь бесплатна по подарку сети, и что
  продление платное.

## Проверки

Юнит: арифметика скидки (потолок, объём сеанса, 0,001 кВт·ч), выбор одного
подарка при `exclusive`, фильтр по минимальному объёму, промокод (нет такого,
чужая сеть, дважды, остановленная кампания), день рождения (29 февраля, раз в
год, не клиент сети), бесплатная бронь (плата ноль, подарок тратится один
раз, залог не тронут, продление платное).

Гонки (одна транзакция, `Idempotency-Key`): два сеанса за один подарок-скидку;
два одновременных ввода одного кода; две брони за один подарок на бронь;
предел по числу подарков при двух одновременных выдачах.

E2e на живой сборке: партнёр собирает кампанию с кодом и скидкой; водитель
вводит код и видит подарок; бронь оказывается бесплатной.
