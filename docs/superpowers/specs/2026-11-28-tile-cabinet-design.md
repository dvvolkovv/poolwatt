# Плиточный кабинет — спецификация

2026-11-28. Требование владельца: кабинет во главе с пользователем, вся
навигация плитками, никаких кнопок-ссылок, в шапке одна кнопка «назад»,
настройки интерфейса с цветом контура плиток и перетаскиванием.

## Что не так сегодня

Проверено по коду, а не по памяти:

1. **Полоса из десяти ссылок.** `src/app/[locale]/me/layout.tsx` рисует
   боковое меню как `flex md:flex-col … overflow-x-auto`. На мониторе это
   колонка слева, на телефоне — ровно та полоса с горизонтальной прокруткой,
   которую видно в кабинете. Десять текстовых ссылок с эмодзи, и половина из
   них человеку не нужна.
2. **Полоса не знает, кто её читает.** «Моя компания», «Подрядчик», «Наряды»,
   «Роуминг» стоят в ней у каждого, даже у аккаунта, который только что
   зарегистрировался и не имеет ни компании, ни наряда. Человек нажимает и
   приходит на пустую страницу.
3. **Пользователя во главе нет.** Имя стоит над меню как подпись и
   `hidden md:block` — на телефоне его не видно вовсе, и нажать на него
   нельзя.
4. **Шапка кабинета несёт две навигации сразу** — свою полосу и гамбургер
   сайта. Для одного экрана это два меню с разными правилами.

## Устройство решения

### 1. Плитки как данные — `src/lib/cabinet/tiles.ts`

Плитка — запись, а не разметка:

```ts
export type TileTarget =
  | { kind: "page"; href: string } // лист: настоящая страница
  | { kind: "group"; group: GroupKey } // узел: вложенная доска плиток
  | { kind: "signOut" }; // единственное действие-плитка

export interface TileDef {
  key: TileKey;
  target: TileTarget;
  /** Без этой способности плитки нет вовсе. */
  needs?: CapabilityKey;
  /** Какую цифру печатать на плитке. */
  value?: TileValueKey;
}
```

Способности человека — `CapabilityKey`: `hasCompany`, `hasAsset`,
`isContractor`, `hasNetwork`, `isCoopMember`, `isStaff`, `isOperator`. Плитка
без своей способности **не рисуется серой, а отсутствует**: обещание, за
которым пустая страница, хуже отсутствия плитки.

Три доски:

| Доска      | Плитки                                                                                                                                                                                                                                                                               |
| ---------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `root`     | Кошелёк, Брони, Избранное, Поддержка, Подарки, Роуминг, Строительство, Моя компания (`hasCompany`), Производитель (`hasAsset`), Сеть зарядок (`hasNetwork`), Подрядчик (`isContractor`), Кооператив (`isCoopMember`), Наряды (`isStaff`), Оператор платформы → группа (`isOperator`) |
| `account`  | Настройки аккаунта, Интерфейс, Выйти                                                                                                                                                                                                                                                 |
| `operator` | Заявки на листинг, Заявки на строительство, Подрядчики, Пункты, Зоны, Роуминг, Контент, Тарифные планы, Сверка, Претензии по чекам                                                                                                                                                   |

Доска `account` — это то, что открывает плитка пользователя: владелец просил,
чтобы нажатие на юзера вело в настройки.

Группы из одной плитки не делаются. Поэтому «Сеть зарядок», «Подрядчик» и
«Производитель» — листы: у каждого уже есть своя страница со своим
содержимым, и прослойка из одной плитки была бы лишним нажатием.

### 2. Цифра на плитке — `src/lib/cabinet/tile-values.ts`

Владелец просил выводить на плитки информацию из шапки. Плитка печатает одну
строку, и только если за ней есть настоящее число:

| Плитка        | Строка                                           |
| ------------- | ------------------------------------------------ |
| Кошелёк       | сумма кВт·ч по всем зонам и деньги основной зоны |
| Брони         | сколько броней впереди                           |
| Избранное     | сколько в избранном                              |
| Поддержка     | сколько заявок открыто                           |
| Подарки       | сколько подарков действует                       |
| Строительство | сколько заявок в работе                          |
| Кооператив    | сколько паёв                                     |
| Наряды        | сколько нарядов на мне                           |

Чего нет источника — на плитке нет строки. Выдуманных чисел не печатаем.
Все значения читаются одним проходом (`readCabinetContext`), как уже сделано
для телефонной оболочки в `readShellContext`.

### 3. Как выглядит плитка

Квадрат с закруглёнными углами (`aspect-square`, `rounded-2xl`), контур
цветом, который выбрал человек, название, под ним строка-значение. Два
столбца на телефоне, три на планшете, четыре на мониторе. Вся плитка —
одна ссылка с явным `aria-label`, то есть палец попадает в любую её точку.

Кнопок, которые выглядят ссылками, в кабинете не остаётся: боковое меню
уходит целиком.

### 4. Шапка кабинета — одна кнопка

Одна кнопка «назад», и её цель вычисляется из адреса, а не из истории
браузера: так она ведёт верно и при переходе по прямой ссылке.

- на `/me` кнопки нет — это и есть дом;
- на доске группы — назад на `/me`;
- на странице раздела — назад на ту доску, которой эта страница
  принадлежит (`root` или `operator`).

Карта «страница → её доска» живёт в том же файле, что плитки, поэтому
кнопка не может разойтись с меню.

### 5. Настройки интерфейса — `/me/settings/interface`

Два умения, оба на человеке, а не на устройстве:

- **Цвет контура.** Шесть названных цветов из палитры темы (акцент,
  зелёный, синий, янтарный, фиолетовый, нейтральный), а не свободный
  выбор: произвольный цвет ломает контраст, и подсветка перестаёт читаться
  в светлой или тёмной теме. Хранится в `User.tileAccent`.
- **Порядок плиток.** Перетаскивание указателем (работает и пальцем, и
  мышью) **плюс** кнопки «выше/ниже» у каждой плитки: только перетаскивание
  недоступно с клавиатуры, а это кабинет, а не игра. Хранится в
  `User.tileOrder` как список ключей.

Сохранённый порядок применяется мягко: незнакомый ключ отбрасывается,
новая плитка дописывается в конец. Значит, человек, получивший компанию
после настройки порядка, увидит новую плитку, а не пустое место.

Миграция: две колонки на `User` — `tileAccent String @default("accent")` и
`tileOrder Json?`.

### 6. Чего эта работа не делает

- Не трогает раздел `/{locale}/app`: у телефонной оболочки своя нижняя
  панель на пять вкладок, она закрыта e2e и работает.
- Не разбивает `/me/settings` на пять страниц. Страница настроек остаётся
  одной, плитка ведёт на неё целиком. Разбивка — отдельная задача, и она
  ничего не ломает, если делать её после.
- Не меняет содержимое ни одной страницы раздела — только то, как до них
  доходят.
- Не открывает ни одного закрытого переключателя.

## Проверка

- Юнит: `tiles.test.ts` — у каждой плитки-листа есть страница на диске (тот
  же приём, что в `site-nav.test.ts`); плитка без способности отсутствует;
  `orderTiles` отбрасывает незнакомый ключ и дописывает новый в конец;
  `parentOf` даёт доску для каждой страницы кабинета и `null` для `/me`.
- Юнит: `tile-values.test.ts` — строка печатается только когда число есть.
- e2e на Pixel 7: на `/me` видна плитка пользователя и плитки квадратные;
  нажатие на пользователя открывает доску `account`; оттуда кнопка «назад»
  возвращает на `/me`; у свежего аккаунта нет плитки «Наряды»; выбранный
  цвет контура переживает перезагрузку; порядок, изменённый кнопкой «выше»,
  переживает перезагрузку.
